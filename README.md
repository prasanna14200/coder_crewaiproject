# CrewAI Coder

This project uses one CrewAI Python developer agent to generate code for a user-supplied assignment. The sequential crew runs the configured `coding_task`; the CLI writes its result to `output/code_and_output.txt`, while the web app returns it as a downloadable response without writing per-request files.

## Model and free tier

The agent is pinned to LiteLLM model `gemini/gemini-3.8-flash`; the server does not accept a model override or fall back to another provider. Google's [model list](https://ai.google.dev/gemini-api/docs/models) lists Gemini 3.8 Flash as stable, and its [pricing page](https://ai.google.dev/gemini-api/docs/pricing) currently lists input and output as free on the **Free** tier. Free tier is limited to eligible models and project-specific RPM/TPM/RPD quotas; inspect your actual limits in Google AI Studio's [Rate Limits](https://ai.google.dev/gemini-api/docs/rate-limits) page. The documentation does not promise one fixed quota for every project. When the Free quota is exhausted, this app stops after two short retries for HTTP 429 and shows a quota message. It never switches to a paid tier or another provider.

Free-tier prompts and responses may be used by Google to improve its products. Do not submit secrets, private source code, or personal data. Keep the Google project on the Free tier: do not link a billing account, enable paid tier, or add a payment method. Do not configure paid services for this app.

Copy `.env.example` to `.env` for local development. `GEMINI_API_KEY` is required. `CREWAI_TRACING_ENABLED` is optional and off by default. `HUGGINGFACE_API_KEY`, `MODEL`, and `SERPER_API_KEY` are not used by the pinned web/agent setup. Keep credentials out of Git.

The previous Hugging Face default was tested and returned HTTP 400 `model_not_supported`; no coding output was generated by that provider. The app now uses only Gemini's documented Free tier. A valid key and Gemini Free-tier access are still required for a real task.

## Install and run

Use Python 3.10 through 3.13 and install the locked dependencies in the project virtual environment:

```bash
uv sync --locked
```

Before involving CrewAI, test one minimal direct model call:

```bash
uv run --no-sync python -m coder.model_check
```

Continue only if this prints `Direct Gemini request succeeded.` If it reports an invalid key, quota limit, or unavailable model, fix the Google AI Studio project/key first. The check makes one request with no retries and at most 48 output tokens.

The CLI uses CrewAI safe code execution and requires a running Docker daemon. Give it a coding assignment as an argument, or omit the argument to run the original series assignment:

```bash
uv run coder "Create a Python palindrome function with example inputs and tests."
```

The hosted web application deliberately disables code execution. It shows and downloads the generated result, but does not run it or claim that its example output has been tested. Review generated code and run it in a sandbox you control.

Run the web app locally:

```bash
uv run python -m uvicorn coder.web:app --host 0.0.0.0 --port 8000
```

Open `http://localhost:8000`. The app accepts one coding job at a time and polls for the result. Its health endpoint is `/healthz`. Job state is held in memory and is lost when the process restarts.

Run the web-interface tests:

```bash
uv run --no-sync python -m unittest discover -s tests -v
```

## Render deployment

Push the project changes to `main`, then create a **Web Service** from `https://github.com/prasanna14200/coder_crewaiproject` on branch `main`.

| Setting | Value |
| --- | --- |
| Root Directory | Leave blank |
| Runtime | Python 3.11 |
| Build Command | `pip install uv && uv sync --frozen --no-dev` |
| Start Command | `uv run --no-sync python -m uvicorn coder.web:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/healthz` |

Set `PYTHON_VERSION=3.11.11` and `GEMINI_API_KEY` in the Render Environment settings. Create the key at [Google AI Studio API keys](https://aistudio.google.com/apikey) and keep its Google project on the Free tier without linking billing. Do not set `MODEL`; the app is pinned to the verified Free-tier model. Render supplies `PORT`; do not set it yourself. Do not add the key to the repository or build command.

This service calls Gemini remotely; it does not load local model weights. The web route disables code execution, so Render does not need Docker. Keep the current Render service on its existing **Free** instance; do not upgrade or enable a paid plan. Render Free has 512 MB RAM and 0.1 CPU and may spin down after 15 idle minutes, so it is suitable only for best-effort testing and can restart under memory pressure. The app serializes jobs in one process; do not scale it to multiple instances without shared job storage. A restart clears active and completed in-memory jobs.

After deployment, verify `/healthz` returns `{"status":"ok"}`, run the direct model check in a local terminal using the same key, then submit a coding task and test the generated code and download. The web service caps assignment input at 1,200 characters, output at 1,024 tokens, allows one active task at a time, and accepts at most 10 tasks per UTC day per running process. It retries HTTP 429 no more than twice (1- and 2-second delays); permanent errors are not retried. These in-memory app limits reset when the process restarts; Google's Free-tier quota is the provider-side limit. A health check or mocked test does not prove a live model call succeeded. The web app does not execute generated code.
